# 03. alethe: orchestration, playbooks and exact commands

## Concepts

| Term | What it is |
|---|---|
| **Lead** | Your session (Claude Opus). Plans, integrates, validates. |
| **Worker** | A CLI running one isolated unit of work (claude, agy, codex, kimi, or a custom one such as opencode). |
| **Playbook** | A sequence of phases and roles (for example `review-gate` = triage, conventions review, bug hunt, validation, fix). |
| **Strategy** | How **one** wave runs: `economy`, `balanced`, `quality`, `research`, `parallel`, `rescue`. |
| **Tier** | `cheap`, `standard` or `strong`, resolved to a model plus effort per provider. |
| **Profile** | A set of tiers and quota limits: `base`, `savings`, `aggressive`. |
| **Goal** | How eager to delegate: `passive` (default), `save`, `balanced`, `max`, `freestyle`. |

Files (global, shared by all projects):
- `~/.config/alethe/alethe-playbooks.yaml`: playbooks, tiers, profiles, adapters (generated by `npx agentic-dev-stack configure-alethe`)
- `~/.config/alethe/orchestrate.json`: policy (provider order, automatic switching, `trust.cwdRoots`)
- `~/.config/alethe/alethe-prices.json`: billing per provider (`subscription` or `api`)
- `~/.config/alethe/orchestrations/`: every orchestration (plans, results, diffs, report)

## Regenerating the profile

```bash
npx agentic-dev-stack configure-alethe           # build the profile for the CLIs that are installed
npx agentic-dev-stack configure-alethe --force   # rebuild it (for example after enabling Codex)
```
From a local clone: `node bin/cli.mjs configure-alethe [--force]`. The old `scripts/configure-alethe.py` no longer exists.

## The stack's `base` profile

| Role | Model |
|---|---|
| planner / validator | lead (Opus) |
| scout (cheap) | agy Gemini Flash `effort high`, fallback Claude Haiku |
| builder (standard) | Claude Sonnet; playbook rules raise it to Opus for `deep`, and `light` stays Sonnet low |
| bug-hunter / reviewer | agy Claude Opus (independent provider), else Codex high, else Claude Opus |
| cheap `cascade` attempt | opencode-safe `9router/free` in an isolated worktree; `risky` goes straight to Claude Sonnet |

To switch profile, tell Claude "use savings", "go aggressive" or "use base".

## Passive mode (how you use it day to day)

You do not have to type any command. With passive mode on (the default):
- the lead delegates cheap, well-bounded units on its own (scouting, mechanical edits with a check, tests, diff review) and tells you in one line;
- before more than 2 parallel workers, or anything expensive, it shows the `dry-run` and waits for your OK;
- small, ambiguous or coupled tasks stay with the lead.

Shortcuts if you want them: `/alethe <task>` · `/alethe status` · `/alethe report html` · `/alethe usage` · `/alethe editor` (opens the playbooks in a visual HTML page) · `/alethe off`.

## Exact command recipe

For the lead (and for you, if you want to run it by hand):

```bash
A=.claude/skills/alethe/scripts/orchestrate.py
python3 $A usage --refresh-claude --refresh-agy   # real quota (otherwise "unknown")
python3 $A playbook --pick                         # which playbook fits
python3 $A new "<title>" --playbook <id> --why "<1 line>" --lead claude:opus
python3 $A scaffold <strategy> --workers N         # plan JSON skeleton (save it OUTSIDE the repo)
python3 $A validate plan.json && python3 $A dry-run plan.json
python3 $A run plan.json --in current --detach && python3 $A wait --timeout 540
python3 $A report            # or: report --format html
```

On Windows use `py -3` (or `python`) instead of `python3`.

```json
  "playbook": "cascade",

  "strategy": "balanced",

  ]

```

## Gotchas (all seen in real use)

| Symptom | Cause | What to do |
|---|---|---|
| `status` answers `error: no runs found` | no orchestration yet | expected; run `new` first |
| quota "5h unknown, week unknown" | no reading yet | `usage --refresh-claude --refresh-agy` (the daily collector does this every day) |
| `mode must be read-only or write` | you wrote `"read"` | only `"read-only"` or `"write"` |
| `scaffold` rejects `review-gate` | scaffold takes a **strategy**, not a playbook | `plan-execute` → `economy` · `parallel-worktrees` → `parallel` · `review-gate` → `research` (reviewers) and `economy` (fix) · `cascade` → `economy` |
| `cwd ... is outside the lead checkout` | worktree outside the repo | `configure-alethe` allows `/tmp` and `PROJECTS_DIR` in `trust.cwdRoots` |
| agy ends with "Please review and approve" | agy plan mode asks for approval | the brief ends with "do NOT create a plan or ask for approval" (already in the profile) |
| agy `permission denied: RunCommand` | agy read mode cannot run a shell | the brief says "file-read tools only"; for a unit that needs a shell, use claude |
| `--model X conflicts with --effort` | agy's Claude models reject effort; Gemini uses a base id plus effort | already solved in the tiers (`gemini-x-flash` + `effort: high`) |
| reviewer reports a "missing file" that exists | it received a hand-filtered diff | always the full diff: `git diff <base>...HEAD > .alethe/review.diff` |
| agy/opencode show no cost in the report | these CLIs do not report dollars | compare by tokens; only Claude reports cost |

## Why both native subagents AND alethe?

| | Native subagent (`scout`/`builder`/`reviewer`) | alethe |
|---|---|---|
| Conversation context | inherits the lead's request | only the brief (files you point to) |
| Providers | Claude only | Claude, agy, Codex, Kimi, any CLI |
| Quota | cannot see it | reads it and switches provider before running out |
| Isolated parallelism | `isolation: "worktree"` | `isolate: true` per writer |
| Cost report | no | `report html` |
| When to use | quick unit that needs the context | several units, another provider, quota savings |

`agent-model-guard` makes sure native subagents never land on Opus by accident.

## Updating alethe safely

1. `git clone` the repo and run `git log ab81104..HEAD` to see what changed.
2. Audit: hooks, network calls, bypass flags, `shell=True` (see [07-security.md](07-security.md)).
3. Change `ALETHE_COMMIT` in `~/.config/agentic-dev-stack/stack.env` and run `./install.sh --workers` (or `npx agentic-dev-stack install --workers`).
4. If `configure-alethe` reports "anchor not found", the playbook format changed upstream: adjust `lib/alethe.mjs`.
