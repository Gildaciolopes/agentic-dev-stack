# 04. Codex, Gemini, Kiro, Copilot: where other CLIs fit

The stack is provider-agnostic. Claude is the default lead, but every piece accepts other CLIs.

## Codex (OpenAI): native fit

Codex is a **native alethe provider** (read-only via sandbox, write via `workspace-write`, resume, quota read from its own session files). It is well worth it if you have ChatGPT Plus/Pro, because subscription quota left over at reset is lost.

### Install
```bash
# in ~/.config/agentic-dev-stack/stack.env: WITH_CODEX=1
npx agentic-dev-stack install --workers    # or ./install.sh --workers
                                           # installs npm @openai/codex + rtk init -g --codex
codex login                                # ChatGPT account
npx agentic-dev-stack configure-alethe --force   # rebuild the profile, now with Codex
```
From a local clone: `node bin/cli.mjs configure-alethe --force`.

### What changes in the profile
- `providers` gains `codex` and the tiers gain `codex: { effort: low|medium|high }`.
- `passive.prefer` becomes `[codex, agy, claude]`: in passive mode, delegable units go to Codex first **while its 5h/weekly windows are fresh and under the limit**.
- Reviewer: with no agy Opus available, the bug-hunter becomes `codex high`. Codex reviewing Claude's code is exactly the "second pair of eyes from another provider".
- Escalation (`fixer` when Claude is low): `codex xhigh`.

### Codex as the lead (instead of Claude)
alethe works the same with Codex as lead: the skill is universal and Codex reads `AGENTS.md`. Install the skill for Codex:
```bash
npx skills add Kc1t/alethe-orchestrate-skill    # pick Codex; or: codex plugin marketplace add Kc1t/alethe-orchestrate-skill
```
The `AGENTS.md` block generated by `npx agentic-dev-stack add-project` already carries the worker rules. On `new`, use `--lead codex:<model>`.

### Token economy in Codex
- `rtk init -g --codex` (done by the installer)
- `headroom wrap codex` for read-heavy sessions
- caveman: the skill works in any agent that reads skills

## Gemini CLI

Personal-account login was discontinued. Options:
1. **agy (recommended):** same Google quota, with Gemini and Claude models. Already a native alethe provider.
2. **Free AI Studio key** (aistudio.google.com/apikey): add it as a provider in 9Router, and Gemini becomes another model in the `free` combo.
3. **Gemini CLI with an API key**, as a **custom** alethe worker (below).

On macOS agy installs through a Homebrew cask; on Linux and Windows download it manually from https://antigravity.google/product/antigravity-cli.

## Any other CLI (Kiro, Copilot CLI, Aider, Cline, Kimi...)

alethe accepts `provider: "custom"` workers. To add one to the profile, edit `~/.config/alethe/alethe-playbooks.yaml`:

```yaml
providers: [claude, agy, opencode, kiro]

adapters:
  kiro:
    command: kiro-cli
    args: [chat, --no-interactive, --trust-tools=fs_read,fs_write]   # the narrowest permission that still writes
    promptTransport: argument      # or stdin
    outputFormat: text             # text | json | jsonl
    modelFlag: "--model"
    checked: "kiro-cli chat --help, 2026-11-01"

tiers:
  cheap:
    kiro: { model: <cheap-model> }
```

alethe rules for custom workers:
- **never read-only** (it cannot guarantee the CLI does not write): always `mode: write` + `isolate: true`;
- flags that approve everything (`--yolo`, `--trust-all-tools`, `--allow-all-tools`, `--auto`, `-y`) are **rejected** unless the policy sets `trust.allowUnsafe: true`, which only you should turn on;
- if the CLI has file access, wrap it in a sandbox like `opencode-safe` (swap the binary in the wrapper).

`npx agentic-dev-stack configure-alethe` only covers Claude/agy/Codex/OpenCode. Customs are added by hand, once.

## Kimi Code

A native alethe provider, but Kimi's prompt mode **always approves everything** (auto). That is why alethe refuses Kimi in read-only mode. Use it only as an isolated writer.

## Free models in any CLI

9Router exposes the `free` combo at `http://127.0.0.1:20128/v1` (OpenAI-compatible). Any CLI that accepts a custom base URL can use it: OpenCode (applied by 9Router), Aider (`--openai-api-base`), Cline, Hermes itself. 9Router's **CLI Tools** screen applies the configuration to several of them automatically. See [05-free-models.md](05-free-models.md).
